- Agentic Payments copy names the active chain's stablecoin and native token through `useStableToken()` (USDC on Base, USD8 on QDay), never a hard-coded symbol; stored activity labels use the `{stable}` placeholder (`fillStable`).
- Spending sessions have no pause or resume: a session is active until it expires or is ended/revoked, and the only controls are End session and Revoke. Registered agents have at most one spending session (approving a new one replaces it) and may have none yet; only agents with a session show View Spending Session. Revoke unregisters an agent, but it is an on-chain transaction: the agent shows "Revoking — awaiting on-chain confirmation" (status `revoking`, access and session still live) and only becomes `revoked` with `revokedAt` once confirmed; if not confirmed it returns to linked with a "Revocation was not confirmed" notice and Try again (preview switch Succeeds/Fails in `RevokeAgentDialog`, settled by `loadQPassState`, nothing is sent); revoked agents are listed under History with their revocation date. Agent cards live in `src/components/agent-list.tsx` (`AgentCard`, `RevokedAgentCard`), with the actions in one pill bar and History cards matching the agent cards.
- Agent registration and spending sessions follow the Signet CLI (`qday-payment-agent-cli`). `signet register agent --signetpass <id>` only links the agent: a plain record with nothing to approve and nothing on chain, so Trellis has no registration approval; the agent just appears in the Agents tab as Linked (with its self-declared vendor and model) and no spending session. A session can start in two ways. (1) The agent's terminal asks (`signet session --per-tx --total --expires-in --task-summary`): the request lands in the Spending Sessions tab with its task summary, and the owner approves it, only able to lower caps and duration. (2) The owner creates it in Trellis: "Create spending session" on the agent card and the agent page opens `CreateSessionDialog` (per-payment limit, total budget, duration; `validateNewSession`: positive amounts, per-payment not above total, whole days up to `MAX_SESSION_DAYS` = 30, the wallet service's ceiling), confirmed with a simulated Passkey and no network-fee row (`createSpendingSession`). Both need an active SignetPass and a linked agent with no usable session (`canRequestSession`); an agent has one usable session at a time, and ending, revoking or expiring it frees it for another. While the agent's own request waits, the card says "Session requested" and offers no Create button (approve that one instead). The preview has no terminal, so two labelled "Preview" buttons stand in for it: "Preview: agent registers" in the Agents tab (`simulateAgentRegistration`, any SignetPass) and "Preview: agent requests a session" on a card without a usable session (`simulateSessionRequest`, then the Spending Sessions tab opens). Approving a request for an agent that was never registered still links it (kept for older sample requests). The approval dialog also shows what the CLI shows the owner: the task summary as a row ("What the agent says this is for", "No summary provided" when empty) in the same list as the limits, the end date if approved now (moves with edited limits), the agent's vendor and model, the blockchain, the session key address (only the address; the agent keeps the key) and a note that one approval registers the session's on-chain identity and installs the session. `CreateSessionDialog` shows the same end date and agent vendor and blockchain, plus an optional task summary (up to `MAX_TASK_SUMMARY` = 140 characters) stored on the session. Neither shows a fee row. "Preview: reset sample data" in the Agents tab (`resetQPassState`) drops every change in this session and restores the sample data for repeating a test. A session created in Trellis is also recorded as an already approved entry (`source: "trellis"`), so Spending Sessions History lists both ways, labelled "Created in Trellis" or "Terminal request". Preview only: nothing is sent or charged.
- The terminal approval dialog is titled "Spending Session Approval" and has no network-fee row. "Edit spending limits" (`SpendingLimitsEditor`) lets the user only lower per-payment limit, total budget and duration (days), and also edit the optional "What is it for?" summary (always shown, up to `MAX_TASK_SUMMARY`; changing only the summary also needs the terminal to re-sign), mirroring the wallet's server-side rules in `validateApprovalLimits`. Save limits runs a simulated server check (preview switch Accepts/Fails); on success the original terminal values stay visible struck through and Approve stays disabled until the terminal re-signs (`CLI_SIGN_MS`, `isAwaitingCli`); on failure edits are kept with an error. Nothing is sent.

- Shopping (`/shop`, a page of its own that stands for a separate shop domain: it is not a tab of the bottom nav, which keeps only Wallet and Agentic Payments, and nothing in Wallet or Agentic Payments links to it) lets the owner search and buy from Trellis, with no agent and no terminal. It is a client-only preview over sample data in `src/lib/shop-preview.ts`, shaped like the Bazaar's `ecommerce` listings (merchant, accepted blockchains, stock snapshot, decimal price) and searched like it: any word matches as the start of a word in name, category, tags or description (a trailing "s" is forgiven), a name match ranks above the rest, results come five at a time ("Show 5 more"). The Filters button (count badge = kinds of filter set, sort not counted) opens `ShopFiltersDialog`, a full-screen popup with the filters the Bazaar search offers a shopper: Category (one), Tags (a product must have ALL of them, at most `MAX_TAGS` = 5), Maximum price (inclusive, `validateMaxPrice`: non-negative decimal, at most 6 decimals; a USDC/USD8 suffix and Under 10/25/50 presets), Shops (`merchantId` whitelist, none = all) and Ships to (`location`: kept when the country is not banned and, if the product lists countries it sells to, is one of them: `sellsTo`). Not offered, on purpose: `type` (Trellis shops `ecommerce` only; `api` listings are for agents), `chain` and `currency` (follow the wallet's blockchain), `payTo` and `environment`. The popup edits a draft and has one Apply button (disabled when nothing matches the draft, with a "No products match these filters." note, or when the price is invalid; no result count); closing it drops the draft and Reset clears the filters but keeps the sort. Sorting is not a filter: it is the quick Sort select on the page (Best match only while there is a search word, Newest, price either way), kept in `ShopFilters.sort`, so it is never a chip or part of the badge count. Only products the merchant accepts on the active blockchain are listed (`chains`: USDC on Base, USD8 on QDay), and the screen follows the Main Wallet's blockchain through the read-only NetworkSummary line, like Agentic Payments, never offering to change it. Prices are decimal strings summed as integer units (`toAtomic`, `formatAtomic`), never floats. Three sub-tabs: Browse (search box; a scrolling row of quick category chips, All plus the active blockchain's categories, which set the same single Category filter as the popup; a row with the Filters button and a Sort select; removable chips for the filters in force; a result count; a list of product rows, one per product), Cart (rows with the product picture, `QuantityStepper` held at the stock and at `MAX_CART_QUANTITY`, remove, the unit price only when the quantity is above one, and a Checkout button that carries the total; there is no separate Total row) and Orders. Product rows (`ProductCard`) show a per-product icon on a tinted tile at the left (`ProductThumb`: hue from the SKU, translucent so it reads in both themes; there are no photos), the shop and category, the price with the stablecoin, a low-stock or sold-out note, and one Add button at the right that becomes a `QuantityStepper` once the item is in the cart, so adding needs no toast (only the product dialog adds with one). Checkout (`CheckoutDialog`) leads with the total, then asks which account pays (the Main Wallets first, then the active SignetPasses on that blockchain; the Main Wallet is preselected), shows the sample ship-to address and the total, refuses with a reason when the balance is short or an item cannot be paid on this blockchain, and confirms with the simulated Passkey. Wallet balances are zero, so a labelled "Preview only" Zero/Sample switch in the dialog lets reviewers reach the paid state. A paid order is listed with its lines at the prices it was bought at, a status badge and a three-step progress (`ORDER_STEPS`: Paid, Shipped, Delivered; status `delivered` follows `shipped`); "Preview: merchant ships the oldest paid order", "Preview: deliver the oldest shipped order" (`deliverOrder`) and "Preview: clear cart and orders" stand in for the merchant and for resetting. In the filters popup and the quick category chips the selected chip is tonal (`border-primary/40 bg-primary/15 text-primary`), per the v5 rule above. Nothing is sent, charged or shipped, balances are not debited, and state lives in a versioned store (currently `trellis-shop-v1`).
