- Keep the post-onboarding wallet overview at `/wallet`, separate from setup, so opening the wallet never restarts onboarding.
- Wallet overview data is explicitly a client-only demo with zero balances and illustrative addresses; never imply it is derived from the demo recovery phrase.
- WalletPreviewProvider shares in-memory illustrative added accounts across wallet, send and receive; never persist or present these as real created wallets.
- Wallet overview keeps a compact "Blockchain · Network" line above the header (NetworkPicker), apart from the wallet name; blockchain and network are chosen in one modal. QDay is the default and Base stays a disabled "Available soon" option with a preview of its setup (new Main Wallet smart account, first one sponsored, then non-sponsored SignetPasses). QDay Mainnet is selectable but always shows a "Preview only, not live" note. The `+` after the pen in the wallet selector row (AddWalletMenu; there is no "My Wallets" title) creates an illustrative wallet in a dialog (default `Wallet N`, editable with the pen) or opens the import page `/wallet/import`; the pen beside the wallet selector renames the selected wallet at any time, which only counts recovery-phrase words and never stores the phrase.
- Wallet overview lists only the default tokens of the active blockchain (QDay: QDAY and USD8; Base later: ETH and USDC, kept in `previewChains`). The `+` beside "Tokens" (AddTokenButton) opens "Import tokens" with a Search tab (labelled sample list per blockchain, multi-select) and a Custom token tab (address, symbol, decimals), then a confirm step. Imported tokens apply to the blockchain and network of the active wallet (each keeps its `networkId`; Aevum Testnet and Base Testnet lists are separate), are zero-balance rows kept in memory only, and never read a contract. There is no Buy/Swap action; QuickSwap code is unused.
- Wallet send/receive screens and action dialogs are client-only previews with real transfers, purchases and swaps disabled; wallet history shows clearly labelled sample rows (not on-chain records) for layout review.
- Apply the shared screen background through the root's `trellis-screen` wrapper and global CSS to each route's phone-column main, so new screens inherit it without per-route background changes.
- ThemeProvider owns the app-wide theme preference, and global semantic tokens define both palettes; keep theme switching out of individual routes so dialogs and menus inherit it too.
- Keep the interactive component catalogue at `/design-kit`, using the same UI primitives as wallet screens so examples remain representative.
- The active blockchain and network live in WalletPreviewProvider and are chosen only on the wallet screen. Agentic Payments shows them as a read-only line (NetworkSummary) above the header; it never offers a way to change them. SignetPasses are picked from a dropdown (scrolls when there are many), not chips. User-facing copy says SignetPass, never QPass or TrellisPass.
- Spending sessions have no pause or resume: a session is active until it expires or is ended/revoked, and the only controls are End session and Revoke. Registered agents have at most one spending session (approving a new one replaces it) and may have none yet; only agents with a session show View Spending Session. Revoke unregisters an agent, but it is an on-chain transaction: the agent shows "Revoking — awaiting on-chain confirmation" (status `revoking`, access and session still live) and only becomes `revoked` with `revokedAt` once confirmed; if not confirmed it returns to linked with a "Revocation was not confirmed" notice and Try again (preview switch Succeeds/Fails in `RevokeAgentDialog`, settled by `loadQPassState`, nothing is sent); revoked agents are listed under History with their revocation date. Agent cards live in `src/components/agent-list.tsx` (`AgentCard`, `RevokedAgentCard`), with the actions in one pill bar and History cards matching the agent cards.
- The terminal approval dialog is titled "Spending Session Approval" and has no network-fee row. "Edit spending limits" (`SpendingLimitsEditor`) lets the user only lower per-payment limit, total budget and duration (days), mirroring the wallet's server-side rules in `validateApprovalLimits`. Save limits runs a simulated server check (preview switch Accepts/Fails); on success the original terminal values stay visible struck through and Approve stays disabled until the terminal re-signs (`CLI_SIGN_MS`, `isAwaitingCli`); on failure edits are kept with an error. Nothing is sent.
- Screens mirrored from qday-trellis-wallet are client-only previews with sample data and a labelled "Preview only" switch for failure states: `/activity` and `/activity/$txId` (sample rows via `TransactionRow`, shared with the `/wallet` history), `/asset/$tokenId`, `/connections`, `/faucet`, `/pq`, `/token-approvals`, `/contacts`, `/watch-address`, `/accounts`, `/account-activation`, `/backup` (demo phrase only, hides after 30 s), `/reset-data` (deletes nothing). They are reached from `/wallet` (See all, token details) and Settings (`Row to=`), not from the bottom nav, which stays Wallet and Agentic Payments.
- Model SignetPass accounts separately from terminal approval requests, linked agents and CLI logins; logout must not silently revoke spending permissions.
- SignetPass is a client-only session-scoped preview initialized after hydration; use a versioned store (currently `trellis-qpass-v15`).
- Create SignetPass (`/agentic/new`) follows the same flow as the first setup: the shared DeploymentFeeNotice (OK, or Top-Up when the Main Wallet lacks USD8), then the name form, then a TransactionConfirm dialog (OK or Cancel). On OK the pass is created and activated, added to the dropdown and selected through `/agentic?pass=<id>`. Preview only: nothing is sent or charged.
- Before the Signet email sign-in, QDayEntry shows a deployment-fee notice (3 USD8 on QDay, 3 USDC on Base, via `signetPassFee`) charged on the Main Wallet; with too little balance it offers Cancel and Top-Up instead of OK. The balance is illustrative, so a labelled preview switch toggles both outcomes. Account and sign-in copy says Signet, not QDay.
- The last setup step is "SignetPass Spending Wallet Activation": Cancel leaves for `/wallet` (progress stays in the session, so returning continues there); Activate Spending Wallet opens a Confirm transaction dialog (3 USD8 gas fee from the Main Wallet) with OK or Cancel. Preview only: nothing is sent or charged.
- The bottom-nav Wallet tab is always reachable, including on every Agentic Payments screen before Signet sign-in or while setup is incomplete, so users can return to their self-custody wallet at any time.
- QDayPreviewProvider owns session-scoped presentation-only sign-in and setup progress; QDayEntry wraps every SignetPass route (agentic, create and agent detail) so direct navigation cannot skip setup. It is not an authentication or wallet-security boundary.
- Only successful recovery confirmation marks the wallet prerequisite for QDay UI previews; this marker never establishes a real wallet connection. QDay setup simulations do not invoke email, WebAuthn or chain services.
- CommentLayer (mounted in the root) owns pick-to-comment review pins: comments anchor to an element by CSS selector plus click offset and are review notes only, never app data. They are stored as GitHub Issues (label `ui-comment`) through the server functions in `src/lib/comments-api.ts`, which keep `GITHUB_TOKEN` server-side (replies are plain comments on the same issue); without a token they fall back to this browser's localStorage.
